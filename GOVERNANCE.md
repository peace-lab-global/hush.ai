# Governance

## Maintainer model

- **Maintainers** are listed in [MAINTAINERS.md](MAINTAINERS.md). They coordinate reviews, releases, and security responses.
- **Contributions** are accepted under the [Apache License 2.0](LICENSE); see [CONTRIBUTING.md](CONTRIBUTING.md).

## Decision making

- Day-to-day changes go through **pull requests** with maintainer review.
- For larger or contentious changes (API shape, defaults, breaking behavior), prefer an **issue** first with a short problem statement and options; link the issue from the PR.
- Consensus among maintainers is the default; if consensus is slow, maintainers may document the rationale in the PR or in [CHANGELOG.md](CHANGELOG.md).

## Security and compliance

- Vulnerability reports follow [SECURITY.md](SECURITY.md).
- This document stays intentionally short; expand sections (e.g. release cadence, RFC process) as the contributor base grows.
